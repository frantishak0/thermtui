# thermtui — температура в терминале

Лёгкий TUI-монитор температур ноутбука: текущие значения, история сессии в виде
графика с горизонтальной прокруткой и шкалой времени, CSV-лог сессии.

Только Python 3.9+ и стандартная библиотека (`curses`) — ставить нечего.
Написан под CHUWI HeroBook Pro (Celeron N4020C), но работает на любом Linux,
где есть `coretemp` / `nvme` / `thermal_zone` в sysfs.

## Запуск

```bash
./thermtui.py                 # обычный запуск
./thermtui.py --interval 5    # опрос раз в 5 секунд (ещё экономнее)
./thermtui.py --duration 600  # закрыться через 10 минут
./thermtui.py --once          # разовый снимок без TUI (для скриптов)
./thermtui.py --once | grep NVMe
```

Чтобы запускать из любого каталога:

```bash
ln -s "$PWD/thermtui.py" ~/.local/bin/thermtui
thermtui
```

## Клавиши

| Клавиша | Действие |
|---|---|
| `q`, `Esc` | выход |
| `←` / `→` | прокрутка графика во времени (шаг — четверть окна) |
| `Home` / `End` | в самое начало / к «живому» краю |
| `Space` | пауза опроса (и записи в лог) |
| `+` / `-` | увеличить / уменьшить интервал опроса |
| `1`..`7` | включить/выключить серию на графике |
| `r` | сбросить min/max сессии |

По умолчанию на графике CPU-пакет, `TCPU` и NVMe; остальные серии включаются
цифрами. Прокрутка «замораживает» окно — новые данные не сдвигают картинку,
пока не нажмёте `End`.

## Логирование

* CSV: время, iso-время, все датчики, частота, нагрузка, питание.
* Лежит в tmpfs (`$XDG_RUNTIME_DIR/thermtui-<uid>/session-*.csv`) — **диск не
  нагружается**, после перезагрузки исчезает.
* Живёт только текущая сессия: при следующем запуске старые файлы удаляются
  (`--keep-log` отключает чистку, `--log-file путь` задаёт свой файл).

```bash
./thermtui.py --log-file /tmp/session.csv
column -s, -t /tmp/session.csv | tail
```

## Почему влияет минимально

| Решение | Что даёт |
|---|---|
| чтение sysfs напрямую | нет `fork+exec` от `sensors`/`lm-sensors` каждую секунду |
| один поток, без тредов и подпроцессов | нет синхронизации и лишних пробуждений |
| интервал 2 с по умолчанию | несколько файлов на датчик, микросекунды работы |
| блокирующий `getch()` с таймаутом | нет busy-loop, процесс спит между опросами |
| перерисовка только при новых данных/нажатии | нет лишнего вывода в терминал |
| лог в tmpfs, построчная запись | нет `fsync` и нагрузки на диск |
| `deque(maxlen=20000)` в памяти | память не растёт |

Измерено на Celeron N4020C: **0.2–0.6 % одного ядра** (интервал 2 и 1 с
соответственно), RSS ~15 МБ. Цифра видна в самой утилите в строке
«расход самой утилиты».

## Датчики

* `coretemp` — пакет и ядра CPU (`Package id 0`, `Core 0/1`);
* `TCPU` — ACPI-зона, ближайшая к кристаллу;
* `acpitz` — зона у чипсета/корпуса;
* `nvme` — температура SSD;
* прочие `thermal_zone*` (кроме виртуальных `INT3400`, `x86_pkg_temp`) —
  если платформа их отдаёт.

**RAM измерить нельзя**: в этом ноутбуке LPDDR распаяна и датчика температуры
у неё нет — ни в `hwmon`, ни в `thermal_zone`. Утилита честно пишет об этом
в строке `RAM`.

## Разработка

`render_test.py` рисует интерфейс в фейковый экран (без терминала) и печатает
кадры для 100x32, 80x24 и 66x20 — удобно проверять вёрстку после правок:

```bash
python3 render_test.py
```

## English

`thermtui` is a tiny TUI temperature monitor for Linux laptops: live sysfs
sensors, a scrollable time-series chart, and a per-session CSV log in tmpfs.
Python 3.9+ stdlib only (curses), ~0.2–0.6 % of one CPU core, no disk writes.
Run `./thermtui.py`, press `q` to quit. `--once` prints a snapshot for scripts.
